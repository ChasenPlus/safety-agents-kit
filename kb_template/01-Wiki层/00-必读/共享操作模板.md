# 共享操作模板（各分支引用）

## 1. 语义检索（sak-rag，全系统统一召回入口）

**检索机制（2026-09起替代search_kb.py/match_regulation/首轮Grep）**：本地向量模型bge-small-zh（ONNX，完全离线）+ SQLite FTS5关键词，RRF融合后由bge-reranker-base cross-encoder对前50候选精排。先做场景识别与query增强（技术×场景×判据，见分支A步骤0a/0a.5），再调MCP工具：

```
rag_search(query="{增强语义query}", top_k=8)
# 定向召回单层（分层补搜/缓存/定位时）
rag_search(query, layers=["企业标准"], top_k=8)
rag_search(query, layers=["清单"], top_k=5)
rag_search(query, layers=["Wiki"], top_k=3)
rag_search(query, layers=["制度目录"], top_k=5)
```

- layers可选值：企业标准/行业标准/国家标准/部委规章/法律法规/清单/Wiki/导航/制度目录；不传=除定责文件外全部层。默认**排除定责文件**，需要时`include_responsibility=true`。
- 模式路由：query含明确"标准号+条款号"（如"GB 50057 4.2.2""第6.1.8条"）→加`mode="keyword"`纯关键词精确命中（自动跳过精排）；其余一律默认hybrid（rerank精排自动生效，勿传rerank=false）。精排模型缺失时自动降级为无精排，仅stderr警告、不报错。
- 每条命中返回：rel_path（源文件相对路径）、layer、clause_hint（条款号）、line_range（行号范围）、score、snippet（仅定位用）、is_ocr。
- **R00铁律：RAG只召回候选——正式引用必须按rel_path打开源文件、按line_range/clause_hint逐字取原文，禁止直接复制snippet**。已知精确"标准号+条款号"用 `python "04-脚本代码/03 A条款检索/search/search_standard_clause.py" --std "{标准号}" --clause "{条款号}"`（回原文环节）。
- 召回不足（top_k未满或最高分<0.35）→ 换同义词/场景词二次召回，最多再搜1次。

**清单失效记录**：`02-原始资料层/05问题分析参考清单/清单失效记录.md`。RAG不识别失效标记，召回的清单候选若已在该记录中标记失效，必须跳过该候选并改用其他来源。新失效用`mark_checklist_invalid.py`追加。

**联网补充管道**：RAG本地未命中 → WebSearch按标准号确认存在；联网获取的内容**必须落盘md并调`rag_upsert_file(path=...)`入库**后才能回原文引用，不直接引用网页摘要。

**索引维护**：知识库文件增删改 → `rag_upsert_file`/`rag_delete_file`；批量后 `rag_reindex(full=False)` 增量同步；`rag_index_status()` 查状态。命令行等价操作：`python "server/rag/rag_core.py" status|reindex|upsert --path|delete --path`。

**注意**：Windows下Python命令是`python`不是`python3`；命令跑不起来（解释器名不对/语法错误）≠"文件夹里没有文件"，先排查命令问题。

**⚠️ R00补充规则：OCR标准件引用强制提醒（用户2026-09-24硬要求，所有分支A/B/C/E/F适用）**：检索到标准md后，先读文件头——若含"OCR"声明（扫描件经`04-脚本代码/04 D标准库管理/ingest/ocr_scanned_pdf.py`转换，统一标记），**凡要把其条款原文作为依据（定责/报告/工作包/修订建议/汇报材料）输出时，必须在引用处或交付说明中主动提醒用户**："本条款出自扫描件OCR转换，可能存在错字、空格、下标丢失（如SF₆→SF），正式引用前请对照同目录同名PDF原件或正式出版物核对"。不得默默引用OCR文字。当前库内OCR件：DL/T 408—2023（2026-09-24入库，PDF同目录）。

## 2.1 sak-excel直接操作台账xlsx前置要求（各分支降级/直读场景共用）

当Bash不可用降级到`sak-excel`直接操作台账xlsx，或需要直接读取某制度编号对应工作表条目时（非通过`append_ledger_entry.py`脚本），**必须先`excel_describe_sheets`确认sheet结构**：

台账xlsx结构 = 1个"汇总"sheet + N个以制度编号命名的制度明细sheet。直接操作前先describe_sheets拿到全部sheet名清单，再按需：
- **写入（append降级）**：先确认目标制度编号sheet是否存在（不存在则先建sheet），再`write_to_sheet`。
- **读取某制度全部条目**：先describe_sheets确认该制度编号sheet存在，再`read_sheet`该sheet；制度编号sheet不存在说明台账无该制度明细记录，不要误读"汇总"sheet或首sheet。
- **读"汇总"sheet的count/version**：直接`read_sheet`"汇总"即可。

**未describe_sheets就直读/直写的常见错误**：误读首sheet（可能是"汇总"而非目标制度明细）、向不存在的sheet写入导致数据错位、漏掉非首sheet的制度记录。

## 3. 标准库失效文件清理（可复用脚本）

**可复用脚本**：`{工作目录}/04-脚本代码/09 跨分支/标准库治理/cleanup_invalid_files.py`

替代原inline命令，一次调用完成空白/乱码/重复文件三类检测，**只检测不删除**，列出清单后由用户逐项确认手工删除。

```bash
# 预览（dry-run，不删除任何文件，只列出失效文件清单）
python "04-脚本代码/09 跨分支/标准库治理/cleanup_invalid_files.py" --kb-root "{工作目录}" --mode dry-run

# 执行（execute，仍只检测不删除，输出更详细的分类统计）
python "04-脚本代码/09 跨分支/标准库治理/cleanup_invalid_files.py" --kb-root "{工作目录}" --mode execute
```

脚本检测规则：
- 空白文件：`.md`内容<50字符或仅含标题行；`.pdf`<1KB
- 乱码文件：`.md`OCR中文字符占比<5%（含"未提取到"标志词）或全文水印重复>10次
- 重复文件：同名不同扩展名算正常（如.pdf+.md），同名同扩展名（如`GB 123-2015.pdf`和`GB 123-2015 (1).pdf`）算重复，hash比对确认

**输出可能很大**（实测1733个空白文件），必要时重定向到日志文件查看：`python "04-脚本代码/09 跨分支/标准库治理/cleanup_invalid_files.py" --kb-root "{工作目录}" --mode dry-run > cleanup_log.txt`

## 5. 图片处理规范

- 尺寸统一：宽度3.5英寸（或用户指定），高度按比例
- 居中对齐，灰色细线边框（#808080）
- 图片说明：图N（单图）或图N-M（多图）
- JPEG2000转换：Pillow `img.save(temp_path, 'JPEG', quality=95)`
- 图片与问题严格对应，不得跨问题借用

## 6. docx格式要求（公文类）

- 标题：方正小标宋简体 22pt
- 一级标题：黑体 16pt
- 二级标题：楷体_GB2312 16pt
- 正文：仿宋_GB2312 16pt
- 行距：29磅固定值
- 首行缩进：2字符
- A4纸，页边距上下2.54cm左右3.17cm

## 10. 现场工作包Markdown六份文档骨架（分支E默认输出格式，生成前必读）

分支E默认输出Markdown时，A组三份、B组两份、培训警示组一份严格按以下骨架与通用件生成，逐字保留抬头、确认段、警示声明框文案，不缩水不改写。

**通用格式声明**（每份文档差异点在该文档内标注）：
- **A组通用抬头**（安全/技术交底共用）：`工作名称：{工作内容}  交底日期：______  交底人：______  被交底人（签字）：______`
- **A组通用交底确认段**（安全/技术交底共用）：`## 交底确认` + 换行 + `被交底人已知悉上述{风险及防范措施 / 技术要求}，签字确认：______________  ______________  ______________`
- **B组通用警示声明框**（两份B组文档共用，参数二选一）：`> 本{文档/卡片}摘录了示例电力企业标准中所有提及本项工作{考核/验收相关}的条款原文，未经"是否足够具体"的筛选，目的是让人员知道"公司制度对这件事确实有{考核要求/完整规定}"，不因不精确而被隐藏。如某条不够具体，建议参照本工作包配套的安全交底/技术交底/应急处置卡执行，或反馈制度归口部门启动修订。`
- **B组通用列表格式**（两份B组文档共用）：`## {制度编号1}《{制度名称}》` + 换行 + `- 第{条款号}条：{原文摘录，R00一字不差}` + 换行 + `（按检索到的制度依次列出，不遗漏任何一条命中记录）`

## 12. 按岗位工作包定制规则（分支E步骤4b生成前必读，仅"按岗位生成"触发）

1. 遍历2e识别出的岗位清单，对每个岗位生成一套七份文档，文件名加岗位后缀：`{工作内容}_{岗位名}_安全交底.md`、`{工作内容}_{岗位名}_技术交底.md`、`{工作内容}_{岗位名}_应急处置卡.md`、`{工作内容}_{岗位名}_考核标准.md`、`{工作内容}_{岗位名}_制度规范卡.md`、`{工作内容}_{岗位名}_专项培训卡.md`、`{项目名称}_{岗位名}_施工方案.md`。
2. **岗位定制规则**（七份文档内容结合该岗位职责调整，不是简单复制）：
   - **安全交底**：危险源辨识侧重该岗位暴露的风险面（如安全员侧重监管履职风险，施工负责人侧重现场指挥风险）；安全技术措施侧重该岗位须执行/须监督的措施。
   - **技术交底**：作业方法与工艺流程侧重该岗位负责的工序（如施工负责人讲全部关键工序，质检员只讲质量验收工序）；技术要求与质量标准按该岗位职责截取。
   - **应急处置卡**：应急处置步骤按该岗位的应急职责定制（如项目经理侧重启动预案/上报，现场作业人员侧重初期处置/撤离）。
   - **工作相关考核标准 / 制度规范卡**：B组两份文档内容本身不按岗位筛选（仍是2b全量摘录），但在文档开头追加一节"本岗位重点适用条款"，从全量摘录中标出与该岗位职责直接相关的条款（标注但不删除其他条款）。
   - **专项培训卡**：培训内容本身不按岗位筛选（仍是2f的training_items），但在文档开头标注"本岗位重点风险类型"，从全部风险类型中标出与该岗位直接相关的风险。
   - **施工方案**：第七章"岗位分工与职责"保留全部岗位（让每人知道协作关系），但用**加粗**标出当前岗位的职责行；其余章节按该岗位职责调整详略（如安全员的施工方案侧重安全保证措施章节，质检员侧重质量保证措施章节）。
3. 岗位数量较多时（如>5个），先列出岗位清单和每套文档的差异化要点让用户确认，避免一次性生成过多重复内容。
