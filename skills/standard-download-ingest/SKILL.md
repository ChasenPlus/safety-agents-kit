# 标准下载入库流水线（获取→校验→OCR→归位→入库→登记）

本技能是 2026-10-03/04 两批真实补缺（32 项正规位 + JGJ59 错配件事件）跑通后固化的 SOP。
执行爬虫相关动作时，同时受《其他杂项/宿主平台智能体提示词/分支D_标准库管理智能体.md》约束
（本系统唯一触发爬虫的入口；删除文件逐项确认；不越权做条款检索/巡查/写材料）。

## 触发与边界

- 适用：用户要求下载/补缺/换版标准、核验已下载 PDF、把散落件归位入库、批量下载后体检。
- 不适用：只查不存（走查询展示，不入库）、条款原文检索（交分支 A）、巡查/整改单（分支 B）、写材料（分支 F）。
- 渠道铁律：只走官方/协会/政府公开页、GitHub/Gitee 公开存档、Internet Archive。
  付费墙与盗版站（道客巴巴 doc88、豆丁、百度文库、book118、guifanku、bzfxw、antpedia、bookzz）
  一律不抓；MCP 返回的 `blocked_candidates` 只展示给用户自行判断。不做验证码绕过。

## 第 0 步 读记忆，不重新摸索

先读 `${SAK_KB_ROOT}\01-Wiki层\20-检索与标准\标准库目录三层整理规范.md`
（重点第八/九/十节）与 `03-输出层\缺失标准下载结果_20261003.md`（33 项失败明细，
失败过的标准号与渠道结论直接复用，不重复攻坚）。笔记与实际目录冲突时以实际为准并提醒更新。

## 第 1 步 获取

1. 行业标准平台有的：`download_standard`（hbba 官方接口），先查询拿 pk。
2. 官方收费/未公开的：`acquire_standard_free(std_no, title, out_root)`。
   代码已内置全部硬拦截，正常情况无需人工逐项判断：
   - 落盘名强制"标准号 标题.扩展名"（URL 解码）；
   - PDF 魔数（%PDF）+ 最小 50KB 体积校验，错误页/预览件直接拒收；
   - 封面标准号身份校验（文字层/扫描件自动 OCR 前 3 页，容错 OCR 变体），
     错配件自动删件换下一候选源（JGJ59 被 8 个 JGJ 查询误配的教训）；
   - MD5 去重；官方/协会域名 tier0 优先于开源存档与普通站。
3. 行为变更后必须重启 宿主平台 才加载新代码；发现返回字段缺 identity_check/health_check
   即说明常驻 MCP 是旧版，停止并提示重启。

## 第 2 步 下载件体检（入库前必做）

- 单批落盘后调 `check_pdf_file(目录绝对路径)` 整目录毫秒级体检。
- `health_check.warnings` 必须如实向用户展示，处置规则：
  - 页数过少（<3）= 预览/截断件，代码已自动拒收删件；漏网的手工确认后删。
  - 双页拼版（横向页占比>50%）= 两页拍成一页，必须拆页后重新 OCR，禁止直接入库。
  - 末页空白 = 下载截断，重新下载或换源。
  - scanned=true 但无拼版/截断告警 = 正常扫描件，走第 3 步 OCR。
  - 加密 PDF = 文字提取可能为空，单独标记请用户处理。
- 身份存疑（校验返回无法判断）时：fitz 渲染封面与末页为 PNG，自行看图核对
  标准号、备案号、发布单位、末页内容（如"引用标准名录"）后再决定。

## 第 3 步 转 MD

- 常规批量：`convert_local_dir`，输出在 `{program_root}/TOMD/{当天日期}/`。
- 单份扫描件：venv python 调 crawler-server 的 `ocr_engine.ocr_pdf_bytes(data, dpi=300)`，
  复杂封面/表格用 dpi=300；md 头必须写 R00 声明（OCR 可能错字，引用前核对原件）、
  来源 URL 与核验过程。
- 已知水印（住建部 16 字、bzfxw）ocr_engine 会自动 strip；转出仍是水印单字
  说明 MCP 旧代码，提示重启。
- 抽查 md 头尾（首屏标准号、最终几条）与 PDF 渲染件一致、无水印残留再归位。

### 图片资产（保真管线入库侧）

数字件（有文字层的 PDF/Word）转换时自动保图，规则（crawler 内部约定，无需手工拼参数）：

- 图片落 md 同级同名子目录 `{md主名}_images/`；PDF 图命名 `p001_01.png`（页号_页内序），
  Word 内嵌图 `d01.png`；md 引用一律相对路径 `![](./{stem}_images/xxx.png)`，
  图注独占下一行。扫描件的整页位图不抽对象，自动按页补 OCR 保文字。
- 降噪规则：<120px 小碎片/蒙版、<页面面积 2%、同 xref 重复图不抽；
  长边>1600 缩放、>2MB 转 JPEG q85。
- **归位/移动 md 时必须把同名 `_images/` 目录一起移动**，引用是相对路径，拆散即断链。
- **入库前自检**：目录内图片落盘数 = md 中 `![` 引用数 = 0 断链（逐条
  `os.path.exists(md目录/引用路径)` 验证）；转换返回的 `images`/`images_total`
  数字应与落盘数一致。归位后再 `rag_upsert_file`，切块器 v3 会把图与所属正文切成
  同块并在检索结果透出 `images` 字段（切块器版本旧/服务未重启时不透出，提示重启）。

## 第 4 步 命名与归位

- 文件名统一"标准号 标题.pdf/.md"（如 `JGJ 59-2011 建筑施工安全检查标准.pdf`）。
- 归位 `02-原始资料层/{国家标准|行业标准}/{行业}/`；out_root 传"行业标准"层本身，
  下载工具内部会建行业子目录，不要再手拼一层。
- DownloadMD 只是暂存区：正规位完成后删除重复件与空查询文件夹。
  - 同一字节流多份重复只留 1 份；错配件若本身是库内没有的正版标准（如 JGJ59），
    核验完整后留一份归位，其余删，并在结果 md 注明"错配件意外增益"。
- 删除纪律（分支 D 硬约束）：逐项列清单请用户确认后再删；批量自动删除仅限
  流水线内当次下载且已被代码校验拒收的文件。乱码件先确认有无清晰替代版；
  过期件先确认新版完整。09-20 批次旧 DownloadMD 件（库内现存数百个已入 RAG 的旧 md）
  非本流水线范围，没有专项指令不动。

## 第 5 步 RAG 入库与核对

1. venv python 进程内 `sys.path.insert(sak-rag-mcp目录); import rag_core;
   idx=rag_core.RagIndex(); idx.upsert_file(md绝对路径)`；文件名含全角"："或
   全半角差异导致 FileNotFound 时用 glob 匹配真实路径。
2. 入库后用标准号+标题关键词 `idx.search(..., layers=[对应层])` 实测命中。
3. 记录文件数/chunks 总数前后变化，与操作份数对得上。

## 第 6 步 清单关联（提示用户，不自动跑）

下载/换版完成后提示用户执行（脚本耗时，不自动执行）：

```bash
python "${SAK_KB_ROOT}\04-脚本代码\link_checklist_standards.py"
```

生成的 md 版清单需再 `rag_upsert_file` 入库，否则清单层召回挂不到新标准。

## 第 7 步 登记与沉淀

- 在 `03-输出层\缺失标准下载结果_{日期}.md` 补记每项：标准号、最终渠道/URL、
  成功/失败、是否扫描件 OCR、有无意外增益；失败项给正版采购建议
  （中国建筑工业出版社/中国标准出版社/企业合规库/openstd.samr.gov.cn）。
- 新教训写入 Wiki 第八节之后顺延编号（渠道、校验、命名、目录任一新坑都记），
  同步检查分支 D 提示词里的"第 X 节"指针是否需要更新。

## 本工作区环境坑

- venv 固定 `d:\工作\AI中心\宿主平台用简化版\.trae\python-venv\Scripts\python.exe`，
  一律 `-X utf8`；中文长 JSON/代码先 Write 成临时 .py 再执行，用完即删。
- 大文件/大目录 LS、Read、DeleteFile、run_mcp 易 IDE 超时；改用 Shell +
  PowerShell（`Get-ChildItem -Recurse`、`Remove-Item -LiteralPath`、
  `[System.IO.File]::WriteAllText` 配 UTF8 无 BOM）。
- KB 在工作区外（${SAK_KB_ROOT}），Edit 易报路径/CRLF 错误，用 Python 脚本读写。
- 含 `[1]` 方括号的文件名必须 `-LiteralPath`，否则被当通配符。
- 不要用 Glob 对 D/C 盘下"找不到"下结论，用 Grep 或 Get-ChildItem 交叉验证。
