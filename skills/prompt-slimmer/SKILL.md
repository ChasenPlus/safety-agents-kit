# 示例集团智能体提示词瘦身

适用对象：`prompts/A_*.md ~ H_*.md` 六个自包含提示词。

**核心原则：减字不减行为。** 只做"外迁"和"去重"，不改变任何运行时规则；用户强调"别多删"时只动确凿项，存疑的一律保留并单列给用户判断。

## 流程

### 1. 量化定位（先数后删，不凭感觉）

```bash
python -X utf8 "skills/prompt-slimmer/scripts/count_sections.py" "prompts/A_clause_retrieval.md"
```

按 `#`/`##`/`###` 标题切节，输出每节字数并标记超过800字的大块。瘦身前后各跑一次做对比。

### 2. 只处理这四类内容

| 类别 | 识别特征 | 处理 |
|:---|:---|:---|
| 技术操作细节 | docx XML属性、美化参数、脚本JSON字段、渲染验证细节，且已被MCP/脚本/模板固化 | 外迁Wiki，留"动手前必读第X节"指针 |
| 格式模板/代码块 | txt记录格式、JSON结构、命令模板，尤其多个分支共用的 | 迁`共享操作模板.md`新增小节，留"按共享操作模板第X节" |
| 重复定义 | Wiki失败教训库已记录的案例、同文件他处已承载的信息（如注册表占位行已替代操作指引） | 删提示词副本 |
| 过时表述 | 分支改名/流程升级后未同步的文字（工具用途、协作方式变化） | 就地修正 |

### 3. 禁止删除（看着长但是运行时行为）

- R03a 出报告依据用户确认门禁、跨分支委托流程与询问话术
- 档位表（#A/#B/#B档/A档等）、三类输出目录表、生成路径优先级
- 严重程度判定标准、定责考核步骤、R00-R13 编号占位（步骤自检按编号锚定）
- 文件中明确标注"务必保留不要精简"的内容（如分支C只读权限警告）
- 自包含架构下**刻意重复**的内容：各分支的跨分支协作表、R08/R17平台兜底规则——单文件部署时删了就不完整

### 4. 外迁目标

- 报告/docx格式与踩坑经验 → `01-Wiki层/10-出报告/出报告经验-格式统一与图片对应.md`，节编号接续现有编号
- 多分支共用操作模板（台账/txt记录/脚本调用） → `01-Wiki层/00-必读/共享操作模板.md`
- 外迁时**完整搬移不缩水**；技术参数、禁项一条不少

### 5. 留指针的写法

替换为：3行以内操作要点（只保留最关键的硬规则/禁项）+ 一句"完整见Wiki层{文件名}第X节"。指针里的节名必须与Wiki实际标题逐字一致。

### 6. 验证（必做，做完才报告）

1. 重跑 `count_sections.py`，向用户报告前后总字数/行数对比。
2. Grep 悬空引用：搜索被删或改名的旧小节标题，确认没有"见上方XX节"指向已删内容。
3. Grep 跨文件残留：被改的规则名、分支名在整个 `prompts/` 目录无旧名残留。
4. 向用户列两份清单：**已处理**（含每处省字去向）和**没动的**（像重复但属于刻意设计/运行时规则）。

### 7. 边界说明

宿主客户端的智能体显示名称、MCP 权限勾选、`mcp.json` 配置不在提示词文件内，瘦身改不到——涉及这些时明确告知用户去宿主客户端设置界面手动处理。
