## 三、台账闭环（调excel-ledger-writer技能，勿手写单元格）

顺序：append（R06b，编号统一写"**2141**"）→ check-threshold（--threshold 2）→ set-confirm-status → 用户Y后交修订起草 → update-status。

**踩坑与对策（都实际发生过）**：
- 编号"Q/BJP 2141"与"2141"会分裂成两个sheet+汇总两行（脚本`sanitize_sheet_name`不归一化编号）。新条目一律写"2141"；发现旧分裂表时合并：迁行（记录日期+触发问题去重，编号规范化）→删旧sheet→汇总删重复行→C/D/F-J字段同步（**上次生成时条目数、上次询问时条目数都设为合并后总数**，否则状态机会误触发重复追问）。合并后跑check-threshold确认`should_ask:false`。
- update-status只更新目标sheet，旧sheet遗留行要单独回写。

## 四、修订建议书docx（python-docx现场写脚本生成）

- 文件名固定：`制度修订建议书_{编号}_{制度名称去书名号}.docx`，输出到 `{知识库}/03-输出层/制度修订编制/`；每次用全部历史条目**覆盖式重生成**（含版本历史表），不是追加。
- 结构：首页强制安全声明（浅黄底表格包裹——**回读校验必须扫表格单元格，只扫paragraphs会漏检**）+七段式（基本信息/版本历史/台账条目表/上位标准原文/条款修订对比/修订说明/评审流程）。
- 红线可视化：修订前红删除线+浅红底、修订后蓝下划线+浅蓝底、新增条款绿底独立块，注明非Word原生track changes。
- **条款号必须回原始docx核实**：MD转换件行号≠条款号（2141曾把5.4.3.4.9误标"第321条"）。
- **原文只读铁律**：2141官方原文只读，建议书是独立新文件；交付前自检全程未对原文件执行过写入。
- 校验：环境无LibreOffice/WPS→程序化回读（七段标题、声明在表格中、strike/underline run计数），并告知用户自行用Word核对排版。
- 临时生成脚本用完即删。

## 五、环境坑（本工作区特有）

- **Glob在D盘/C盘一律返回No file found，不能据此判定文件不存在**——用Grep或Shell+`Get-ChildItem -Recurse`交叉验证。
- PowerShell不支持`&&`，多命令用`;`分隔。
- 中文长JSON不进命令行：先Write成`.py`脚本再`python -X utf8`执行，用完删除。
