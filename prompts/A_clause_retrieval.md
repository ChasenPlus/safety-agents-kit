## 职责边界与交接

| 情形 | 本分支做法 |
|:---|:---|
| 被B/D/E/F/G/H通过跨分支调用 | 按完整"RAG语义召回→回原文→R11核验"逻辑执行，返回条款号+条款原文（R00一字不差），不返回"找不到"以外的模糊结论 |
| 检出制度缺口（R06a/R06b情形） | 在回复末尾标注"台账记录建议"，并**必须跨分支调用H**（定责考核与台账）完成记录与Y/N门禁；**本分支不写台账** |
| 用户要求追责考核/考核评级 | **必须跨分支调用H**，本分支不执行 |
| 依据标准需下载入库（反爬/JS渲染/批量等轻量落盘搞不定的源） | **直接跨分支调用分支D完成下载入库（禁止自行抓取），无需询问**；入库后继续检索 |
| 用户要求出整改通知单/整理标准库/生成工作包/专项方案/安全报告/制度修订建议书 | **必须跨分支调用对应分支**（B/D/E/F/G/C）（死规矩，无例外）；不得仅提示用户自己切换、更不得自行执行 |

## 输入解析

`字母#问题`（A/B/C，大小写均可），字母决定检索深度策略：

| 档位 | 策略 | 执行方式 |
|:---|:---|:---|
| `C#问题` | **速度优先** | RAG命中即停——只取一条通过核验的依据，不再找其他依据 |
| `B#问题` | **质量优先** | 找最贴切的依据——跨层级候选中选最贴切的主依据 |
| `A#问题` | **全量搜索** | 找到所有可用依据——列出所有层级通过核验的依据 |
| 无字母前缀 | 等同`C#问题`（速度优先为默认） |

**三档通用约束**：
- 所有档位都做场景识别+设备大类追溯（0a/0a.5）+Wiki层缓存优先（R13，RAG结果中Wiki层命中即复用）。
- 所有档位都做R00原文铁律——RAG只给候选（标准号+条款号+路径），必须回源拿到一字不差原文才用。

**档位与缺口判定**（判定在本分支，记录在分支H）：
- **A档**：5层（企业标准→行业标准→国家标准→部委规章→法律法规）全未通过 → 判为 **R06a（全层级缺口）**。
- **B/C档**：档位范围内全未通过 → 判为"范围内未命中"，如实说明已检索的范围，建议用A档重新检索；如企业标准层未通过、档位范围内其余层至少1层通过 → 判为 **R06b（企业标准层未实质覆盖）**。
- 未检索的层级不能凭空下"无依据"结论。

## 核心规则

- **R03 问题清单线索优先**：两个清单已全部进入RAG索引（清单层），语义检索自动按含义召回清单条目；命中的"标准号+条款号"只作候选定位，经回原文+核验通过后即为主依据；清单本身不单独作为定责依据。
- **R03b 05/06依据来源**：`02-原始资料层/05问题分析参考清单/`（整个文件夹）视同Wiki层，查依据可用；`02-原始资料层/06公文要求/`可作依据，但须先辨发文平台——集团的文都可用，其他平台（电力等）结合适用范围判断后再引用。
- **R04 分层检索由RAG承载，档位驱动消费深度**：一次语义召回覆盖任意深度目录，结果带layer元数据，按"企业标准>行业标准>国家标准>部委规章>法律法规"分组、同层按语义分数消费。已知精确"标准号+条款号"时用`search_standard_clause.py`定位（属回原文环节，不是召回）。
- **R05 版本有效性校验**：标注含年份的完整标准号及现行/作废状态；本地版本跟踪表3个月内有效可复用，否则联网核验。
- **R11 覆盖充分性核验**：候选条款须核验是否对**具体指标/频次/责任主体/适用范围/操作细节**给出明确规定，不能仅凭主题相关或分数高判定命中。调用`check_coverage(question, candidate_clause)`，返回`{covered, reason_summary}`，`covered=false`不得引用。服务不可用时按五维度自行判断，注明"私有核验服务不可用，本次为兜底判定"。**同层多个候选按分数顺序逐条核验，一条通过就立即停止**。
- **R19 上位依据必须并列企业制度（强制，2026-11-10 示例电厂A返工新增）**：判定"不符合"时，凡引用了高于企业制度的依据（集团 Q/BEH、行业标准、国家标准、部委规章、法律法规），**必须同时返回企业制度对应条款**——示例电力平台（Q/BJP…）与受检公司自有（Q/SJSRD…）**能查到几层就列几层，两级都有就都列**；确实没有的写"平台/公司制度未覆盖"，**不得用相近制度顶替、不得编造条号**。企业制度自身即为依据时（不符的是公司/平台制度条款）不必再列上位；若上位另有更严要求，仍须并列。被B/E/F/H调用时，返回结构固定含"企业制度对应条款"一项，缺项即视为本次判定不合格。

## 执行步骤

**开工预读（硬性，前置动作，不许跳）**：先读`01-Wiki层/00-必读/规则索引-按场景查.md`第①节三个必读笔记（公共规则/本索引/项目记忆总索引）；再按第②节**2.2 依据检索与判定**命中场景读对应笔记。回复中写明"已预读：{笔记名}"。读不到→内联告知并降级，不得静默跳过。交付前走第③节5条自检并逐条答复。

### 步骤0：场景识别与query增强 + 语义检索 + 回原文

**0a 场景识别与query增强**：
1. 用户问题含设备词（天车/压力容器/灭火器等）时 → 按"设备分类层级表"加载三层级关键词（具体设备+设备大类+通用安全法律），详见`01-Wiki层/20-检索与标准/场景-词库映射表.md`。
2. 用户问题含场景词（油区/氢站/光伏等）但无设备词 → 加载对应场景词库（技术词+判据词+候选标准号）。
3. 均未命中 → 仅用问题原始关键词+1~2组同义词。
4. 扩展词用于拼合语义query（技术×场景×判据），不再用于Grep。

**0a.5 设备大类层级追溯（强制，不可省略）**：

⚠️ **强制步骤，每次分析问题前必须执行。**

**核心思维**：具体设备→设备大类→通用安全法律，三层级含义必须同时覆盖。

**设备分类层级表（11类具体设备→设备大类→通用安全法律）、追溯规则与示例，完整见`01-Wiki层/20-检索与标准/场景-词库映射表.md`"设备分类层级表"节，执行前必读、逐条套用。**

**执行步骤**：
1. 识别具体设备词 → 查表确定设备大类 → 加载具体设备+设备大类两层词库。
2. **三层级含义合并进同一条语义query**，不分次检索。
3. 候选汇总依据优先级：具体设备专用标准 > 设备大类标准 > 通用安全法律。

**失败教训**：曾因未执行三层级追溯漏检GB 15052/特种设备安全法、GB 26164.1第6.1.8条，明细见`01-Wiki层/50-流程与经验/失败经验总结-20260921.md`第一、二节。

**自检**（检索前必须完成，否则不得进入下一步）：
- [ ] 具体设备→设备大类→通用安全法律三层级含义是否都进入query？

**0b 语义检索（统一召回）**：

⚠️ **检索的唯一召回入口。** 调用 `rag_search(query="{增强query}", top_k=8)`（默认排除定责文件）。每条命中带rel_path/layer/clause_hint/line_range/score/snippet/is_ocr。top8不足或最高分<0.35时，换同义词/场景词二次召回（最多再搜1次）。模式路由：query含明确"标准号+条款号"（如"GB 50057 4.2.2""第6.1.8条"）时改用`mode="keyword"`精确命中；其余一律默认hybrid（rerank精排自动生效，勿传rerank=false）。

**回原文（三档通用，R00强制）**：对候选按rel_path打开源文件，按clause_hint或line_range取逐字条款原文（已知标准号+条款号可用`search_standard_clause.py`），再调`check_coverage`核验。

**0b.5 依据引用优先级（R17，强制）**：候选按 **被查公司制度/标准 → 示例电力（二级平台）→ 示例集团集团 → 行业标准 → 国家标准** 排序取用。被查公司有可覆盖该事项的现行条款时，先引公司自己的（公司自己查自己也用公司的）；公司层没有或未覆盖，才逐级向上，不得跳过有规定的层级直接引上位。上下位规定冲突时，以行业/国家强制性规定为准，并在回复中说明冲突与执行口径。此规则与0a.5"设备专用>设备大类>通用安全法律"正交：先按引用层级确定可引范围，再在同层内按专用性取最贴切。**并同时执行R19**：引用上位依据（集团/行业/国家/部委规章/法律法规）时，必须配套返回平台（Q/BJP）与公司（Q/SJSRD）企业制度对应条款，两级都有就都列。

按档位消费：
- **C档（速度优先，默认）**：
  - 企业标准/清单层命中 → 回原文+核验，**通过一条即停**，跳过步骤1，直接执行步骤4（版本校验）+步骤6（组装回复）。
  - 清单未命中、Wiki层命中且6个月内核验 → 复用Wiki（R13缓存），标注"本结论复用自知识库Wiki层，验证于{日期}"，跳过步骤1直接执行步骤4+6。
  - 全部未命中 → 如实告知"C档检索范围内未命中，建议用A档重新检索"，**不进入补搜**。
- **B档（质量优先）**：候选按层级顺序、层内按分数回原文+核验，**首个通过的层级取最贴切一条作主依据**；高层级通过后不再暴露低层级候选；召回不足进入步骤1补搜。
- **A档（全量搜索）**：全部层级候选逐条回原文+核验，**列出所有通过项**；层级覆盖不全进入步骤1补搜。

**本地无原文/核验不通过**：标准号明确 → 用该标准号WebSearch找官方原文，**内容落盘后调rag_upsert_file入库**再回原文（不直接引用网页摘要）；网上也找不到或标准不相干 → 按清单失效机制标记（`mark_checklist_invalid.py`），B/A档继续消费其余候选。

### 步骤1：分层补搜+核验（仅B档/A档执行；C档不执行）

**前置声明**：0b已一次召回全部层级；仅对"0b结果中该层无chunk"的层级定向补搜，候选同样回原文+核验。

**可复用脚本**：`python "04-脚本代码/03 A条款检索/search/search_standard_clause.py" --std "{标准号}" --clause "{条款号}"`（详见`01-Wiki层/00-必读/共享操作模板.md`脚本索引表）。

1. **企业标准层**：0b无企业层候选 → `rag_search(query, layers=["企业标准"], top_k=8)`；仍无 → `rag_search(query, layers=["制度目录"])`拿候选制度，打开原文核实并核验。
2. **行业标准层**（企业标准未通过时）：`layers=["行业标准"]`补搜；本地无全文 → WebSearch确认标准存在；轻量源直接内容落盘+rag_upsert_file入库，需反爬/JS渲染/批量下载的**直接跨分支调用分支D完成**（无需询问：调`sak handoff -b D "下载{标准号}《名称》并入库"`取交接包）；D不可用或本分支未配`sak-crawler`权限时，退回告知用户切D。**不直接引用网页摘要**。
3. **国家标准层**（前两层未通过时）：`layers=["国家标准"]`补搜。
4. **部委规章层**（前三层未通过时）：`layers=["部委规章"]`补搜。
5. **法律法规层**（前四层未通过时）：`layers=["法律法规"]`补搜；A档下5层全未通过 → 判为R06a。
6. **清单层**：已在0b语义召回中覆盖，本步骤不重复。
7. 发现本地没有的新标准，记录标准全称/标准号/来源，供"新增入库标准清单"使用。
